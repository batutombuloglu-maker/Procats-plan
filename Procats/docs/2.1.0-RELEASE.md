# Procats 2.1.0

## Knowledge Collection

- Open Knowledge Collection from the desktop sidebar or the mobile More menu.
- Add cards to the built-in Words, Concepts, and General Knowledge collections, or create a custom collection.
- Assign a card to multiple collections. All cards shows each card once. Use the card's three-dot menu to edit or delete it.
- Review the cards in the current selection by revealing each answer in turn.
- A verified account syncs collections across devices. Guest collections stay on the current device.

## Import the sample pack

1. Open **Data Vault → Add data** in Procats 2.1.0.
2. Select `Procats-Bilgi-Koleksiyonu-Ornekler.json` from the release's `08-Ornek-Veri` folder.
3. Check the import preview and confirm. The pack contains ten cards and the custom collection **Sınavda çıkanlar**. The card **Mahir** belongs to both Words and that collection.

The additive import preserves existing records. An identical import skips records already present.

## Account and backup compatibility

Knowledge Collection uses the existing account archive transport and the existing Firestore rules. Its records are kept separate from older archive entries in the app. Older archive entries remain in encrypted backups and are covered by account deletion.

## Build and update

- **Web**. Use Node.js 22 or newer. Run `npm ci`, `npm test`, and `npm run build` in `Procats`. A public checkout builds with example Firebase settings. Use your own project configuration and the included Firestore rules to enable live accounts.
- **Android and Wear OS**. Use JDK 21 and Android SDK 36. Build the web client, then run `npx cap sync android`. The personal variants use `com.procats.study.personal`. The phone version code is 36 and the watch version code is 37. Use the same signing certificate when updating an existing personal installation.
- **Windows**. Install dependencies in `Windows` and copy the web build to a fresh `Windows/www` folder. Run `npm test` and `npm run dist` there. The x64 installer and portable executable use the same web build and are unsigned.

Keep the signing key and encrypted personal backups outside the public repository.
